# Prototype data flow

This describes the local Poolser web prototype, not the native application's storage or the future hosting service. There are no user accounts, wallet connections, transaction submissions, analytics or tracking integrations.

- **Infura:** when selected, the browser sends chain reads, public wallet addresses and contract/log queries directly to `mainnet.infura.io` using the API key entered in the form. Infura's API requires the key in its RPC endpoint path. Poolser does not put the key in the page URL, browser storage, source files or application logs, and its error messages do not echo provider URLs or raw provider messages. Browser developer tools can still display requests made by the user's own browser.
- **Public dRPC:** when explicitly selected, the same chain queries are sent directly to `eth.drpc.org`; no Infura key is sent. Public-provider rate/range limits may prevent a complete scan in one refresh.
- **CoinGecko / DefiLlama:** the browser requests USD prices by token contract address from `api.coingecko.com` and `coins.llama.fi`. The app does not send wallet addresses or the Infura key to price services. On-chain contract reads supply symbols and decimals.
- **Artwork:** live token logos are fetched from `token-icons.llamao.fi` by numeric chain ID and token contract address; network artwork uses the configured `coin-images.coingecko.com` URL, matching the native sources. These requests omit credentials and referrers and do not contain the wallet address or Infura key. Positive images stay in memory as blob URLs until the page ends. A missing (404) logo is retried after a week; transient/invalid/decode failures after an hour. Cache state is memory-only, so reload resets it. Requests time out after 10 seconds and accept bounded raster images; a failed logo keeps a deterministic glyph/colour placeholder.
- **Browser storage:** the last entered public wallet address, v4 scan cursor, candidate NFT IDs and learned window size are stored locally. Browser storage can be cleared, unavailable or evicted; a visible notice explains when progress cannot be saved. No API key or portfolio snapshot is persisted. Clearing a saved scan removes that wallet's discovery checkpoint.
- **Memory:** the key and current portfolio are held in the page's memory. Reloading requires re-entering the key. Forget API key clears the form value. Navigating away ends the page session. No background polling occurs after the page is closed.
- **Demo:** fictional in-memory positions require no RPC, price or external artwork requests or saved wallet configuration. The demo token/network artwork is bundled locally; its public sources and hashes are recorded in `public/icons/sources.json`.

The developer receives no wallet addresses, API keys or portfolio data through this application. RPC/price providers can observe requests sent directly to them under their own policies. The local Vite server serves application files; it does not proxy chain/price requests. Actual production hosting logs, support contacts, origin restrictions and response security headers must be reviewed before publication in the separate hosting/release milestones.

Poolser is independent of Uniswap Labs and the Uniswap Protocol. Private keys and signing remain outside this read-only prototype.
